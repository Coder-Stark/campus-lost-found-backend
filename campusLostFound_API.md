# Campus Lost & Found API — Validation Testing

Base URL:

```text
http://localhost:5000
```

## 1. Test GET Items

### Request

```http
GET /api/items
```

### Full URL

```text
http://localhost:5000/api/items
```

### Expected response

```json
{
  "success": true,
  "data": []
}
```

If items have already been created, the `data` array will contain those items.

# 2. Test POST — Missing Required Fields

This test verifies that the API rejects a request when required fields are missing.

### Request

```http
POST /api/items
Content-Type: application/json
```

### Body

```json
{}
```

### Expected response

**Status:** `400 Bad Request`

```json
{
  "success": false,
  "error": "Validation failed",
  "details": [
    {
      "field": "title",
      "message": "Invalid input: expected string, received undefined"
    },
    {
      "field": "type",
      "message": "Type must be either Lost or Found"
    },
    {
      "field": "location",
      "message": "Invalid input: expected string, received undefined"
    },
    {
      "field": "contactMethod",
      "message": "Invalid input: expected string, received undefined"
    }
  ]
}
```

# 5. Test POST — Valid Item

This test verifies the complete successful flow.

### Request

```http
POST /api/items
Content-Type: application/json
```

### Body

```json
{
  "title": "Black Water Bottle",
  "type": "Found",
  "location": "Central Library",
  "contactMethod": "test@example.com",
  "date": "2026-09-02T10:30:00+05:30",
  "description": "Found near the reading room"
}
```

### Expected response

**Status:** `201 Created`

```json
{
  "success": true,
  "data": {
    "_id": "generated-mongodb-id",
    "title": "Black Water Bottle",
    "type": "Found",
    "location": "Central Library",
    "contactMethod": "test@example.com",
    "date": "2026-09-02T10:30:00+05:30",
    "description": "Found near the reading room",
    "createdAt": "generated-timestamp",
    "updatedAt": "generated-timestamp"
  }
}
```

The actual `_id`, `createdAt`, and `updatedAt` values will be generated by MongoDB/Mongoose.

# 6. Verify Persistence

After successfully creating an item:

### Request

```http
GET /api/items
```

### Full URL

```text
http://localhost:5000/api/items
```

The newly created item should appear in the response.

The item is stored in MongoDB Atlas, so it should remain available even after restarting the backend server.

# API Summary

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| GET | `/api/items` | Retrieve reported items | `200` |
| POST | `/api/items` | Create a new report | `201` |
| GET | `/api/unknown` | Test unknown route handling | `404` |
